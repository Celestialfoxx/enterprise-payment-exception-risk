# Methodology

## Research objective

The objective is to test whether synthetic workflow and control-related signals can be used to predict whether an enterprise payment request is likely to require manual exception review.

The prototype focuses on one binary classification task:

- `0`: payment request does not require exception review.
- `1`: payment request requires exception review.

## Data generation

The project uses synthetic data generated by `src/data_generator.py`. The data includes operational signals that are plausible in enterprise payment workflows:

- invoice amount
- approval lag
- days until due date
- supplier risk tier
- payment method
- business unit
- prior exceptions in the last 90 days
- recent account-change indicator
- duplicate invoice signal
- missing supporting document indicator
- policy flag count
- approval chain length
- scheduling pressure

The label is generated from a controlled latent-risk formula with random noise. This makes the experiment reproducible while avoiding real financial, supplier, customer, or payment data.

## Baseline method

The baseline is a logistic regression model using only three features:

- invoice amount
- approval lag days
- supplier risk tier

This baseline represents a simple and interpretable starting point.

## Improved method

The improved method is a random forest classifier using a richer set of workflow features. It is still lightweight and runs quickly on a laptop, but it can capture nonlinear relationships between payment workflow signals.

## Evaluation

The models are evaluated using:

- accuracy
- precision
- recall
- F1 score
- ROC AUC
- average precision
- confusion matrix counts

The F1 score is useful because exception review is a prioritization problem where both false positives and false negatives matter. ROC AUC and average precision provide threshold-independent views of ranking quality.

## Reproducibility

Random seeds are fixed in data generation, train-test splitting, and model construction. Running `python experiments/run_experiment.py` from the repository root regenerates the dataset, trains both models, saves outputs, and prints model metrics.
